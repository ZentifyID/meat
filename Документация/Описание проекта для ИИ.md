# Описание проекта для другого ИИ

## Кратко о проекте

Это небольшой сайт на Django для компании по производству и продаже мясной продукции. В интерфейсе используется бренд `Мясной Двор`. Проект совмещает обычный серверный рендеринг HTML-шаблонов Django и JSON API, через который JavaScript на клиенте загружает товары, новости, отзывы, корзину, профиль и оформляет заказы.

Основные возможности сайта:

- просмотр главной страницы с описанием компании, преимуществами, партнерами и отзывами;
- просмотр каталога продукции с поиском и фильтрацией по категориям;
- просмотр карточки товара и добавление товара в корзину;
- управление корзиной через AJAX: добавление, изменение количества, удаление;
- оформление заказа;
- регистрация, вход и выход пользователя;
- личный кабинет с историей заказов и отзывами пользователя;
- публикация отзывов после модерации администратором;
- раздел новостей компании;
- административная панель Django для управления товарами, категориями, заказами, отзывами и новостями.

## Технологии

- Backend: Django.
- База данных: SQLite по умолчанию, файл должен находиться в `meatdjango/db.sqlite3`.
- Frontend: Django Templates, обычный JavaScript без сборщика, CSS.
- Хранение корзины: Django session.
- Загрузка изображений: `ImageField`, файлы в `meatdjango/media/`.
- Статика: `meatdjango/static/`.
- HTML-шаблоны: `meatdjango/templates/`.

В проекте не найден `requirements.txt`, поэтому зависимости нужно уточнять по окружению. По коду очевидно нужен Django и библиотека для работы с изображениями, обычно `Pillow`, так как используются `ImageField`.

## Настройки Django

Файл: `meatdjango/meatdjango/settings.py`.

Важные настройки:

- `DEBUG = True`, проект настроен для разработки.
- `ALLOWED_HOSTS = []`.
- Подключено приложение `meatsite`.
- База данных SQLite: `BASE_DIR / 'db.sqlite3'`.
- Шаблоны берутся из `BASE_DIR / 'templates'`.
- Статика: `STATIC_URL = '/static/'`, `STATICFILES_DIRS = [BASE_DIR / 'static']`.
- Медиа: `MEDIA_URL = 'media/'`, `MEDIA_ROOT = BASE_DIR / 'media'`.
- В context processors добавлен `meatsite.context_processors.cart_count`.
- Авторизация:
  - `LOGIN_URL = 'login'`;
  - `LOGIN_REDIRECT_URL = 'profile'`;
  - `LOGOUT_REDIRECT_URL = 'home'`.

В `meatdjango/meatdjango/urls.py` подключены:

- `/admin/` - Django admin;
- `/` - все маршруты приложения `meatsite`;
- media-файлы в режиме `DEBUG`.

## Модели данных

Файл: `meatdjango/meatsite/models.py`.

### Category

Категория товаров.

Поля:

- `name` - название категории;
- `slug` - уникальный slug.

Особенности:

- slug генерируется автоматически при сохранении;
- есть транслитерация русских символов в латиницу;
- при совпадении slug добавляется суффикс `-2`, `-3` и так далее.

### Product

Товар каталога.

Поля:

- `name` - название;
- `slug` - уникальный slug;
- `description` - описание;
- `price` - цена `DecimalField`;
- `image` - изображение товара, загружается в `media/products/`;
- `available` - доступность товара;
- `category` - связь с `Category`.

Особенности:

- slug также генерируется автоматически;
- `get_absolute_url()` ведет на страницу товара `/products/<slug>/`.

### Order

Заказ.

Поля:

- `user` - пользователь, может быть `null`, если заказ оформлен гостем;
- `full_name` - ФИО;
- `phone` - телефон;
- `email` - email, необязательный;
- `address` - адрес доставки;
- `created_at` - дата создания;
- `is_paid` - флаг оплаты;
- `status` - статус заказа.

Статусы:

- `processing` - В обработке;
- `delivery` - Доставка;
- `completed` - Выполнено;
- `canceled` - Отменен.

Методы:

- `get_total_price()` - сумма по всем позициям заказа;
- `status_css_class` - CSS-класс вида `status-processing`.

### OrderItem

Позиция заказа.

Поля:

- `order` - заказ;
- `product` - товар;
- `quantity` - количество.

Метод:

- `get_total_price()` - цена товара, умноженная на количество.

### Review

Отзыв клиента.

Поля:

- `user` - пользователь, если отзыв оставлен авторизованным пользователем;
- `name` - имя автора;
- `city` - город, необязательный;
- `rating` - оценка от 1 до 5;
- `text` - текст отзыва;
- `created_at` - дата создания;
- `is_published` - опубликован ли отзыв.

Особенности:

- отзывы сортируются от новых к старым;
- новые отзывы через API создаются с `is_published = False`, то есть требуют модерации в админке.

### News

Новость компании.

Поля:

- `title` - заголовок;
- `short_description` - краткое описание;
- `content` - полный текст;
- `image` - изображение новости, загружается в `media/news/`;
- `created_at` - дата создания;
- `published_at` - дата публикации;
- `is_published` - опубликована ли новость.

Особенности:

- новости сортируются по `published_at`, затем по `created_at`, новые выше;
- публичный API отдает только опубликованные новости.

В админке зарегистрированы:

- `Product`;

- `Order`;

Возможности:

## JSON API

Все API endpoints реализованы в `meatdjango/meatsite/views.py`.

### Авторизация

`GET /api/auth/session/`

- Возвращает информацию о текущей сессии.
- Если пользователь не авторизован: `{ "is_authenticated": false, "user": null }`.
- Если авторизован: id, username, full_name, email.

`POST /api/auth/register/`

- Принимает JSON: `username`, `email`, `password1`, `password2`.
- Валидирует через `RegisterForm`.
- Создает пользователя и сразу логинит его.
- Возвращает `redirect_url` на профиль.

`POST /api/auth/login/`

- Принимает JSON: `username`, `password`.
- Логинит пользователя через `authenticate`.
- Возвращает `redirect_url`.

`POST /api/auth/logout/`

- Завершает сессию, если пользователь авторизован.
- Возвращает `redirect_url` на главную.

### Отзывы

`GET /api/reviews/`

- Возвращает до 6 опубликованных отзывов.

`POST /api/reviews/`

- Принимает JSON: `name`, `city`, `rating`, `text`.
- Если пользователь авторизован и имя не указано, имя берется из профиля.
- Создает отзыв на модерации.

### Новости

`GET /api/news/?limit=12&offset=0`

- Возвращает список опубликованных новостей.
- Есть простая пагинация: `total`, `limit`, `offset`, `has_next`.

`GET /api/news/<news_id>/`

- Возвращает детальную информацию об опубликованной новости.
- Если новость не опубликована или не найдена, возвращает 404.

### Профиль

Все endpoints профиля требуют авторизации через кастомный декоратор `_api_login_required`.

`GET /api/profile/`

- Возвращает данные текущего пользователя.

`GET /api/profile/orders/`

- Возвращает заказы текущего пользователя с товарами, статусом, датой и суммой.

`GET /api/profile/reviews/`

- Возвращает отзывы текущего пользователя, включая неопубликованные.

`DELETE /api/profile/reviews/<review_id>/`

- Удаляет отзыв текущего пользователя.

### Категории и товары

`GET /api/categories/`

- Возвращает список категорий: `id`, `name`, `slug`.

`GET /api/products/?category=<id>&q=<search>`

- Возвращает список товаров.
- Фильтр `category` работает через ORM.
- Поиск `q` выполняется в Python через `casefold()` по названию товара.
- Возвращаются id, slug, name, description, price, available, category, image_url, detail_url.

### Корзина

Корзина хранится в `request.session["cart"]` как объект вида:

```json
{
  "1": { "quantity": 2 },
  "5": { "quantity": 1 }
}
```

`GET /api/cart/`

- Возвращает товары корзины, общую сумму и общее количество.

`POST /api/cart/items/`

- Принимает JSON: `product_id`, `quantity`.
- Добавляет доступный товар в корзину.
- Если товар уже есть, увеличивает количество.

`PATCH /api/cart/items/<product_id>/`

- Принимает JSON: `quantity`.
- Обновляет количество.
- Если количество `<= 0`, удаляет товар из корзины.

`DELETE /api/cart/items/<product_id>/remove/`

- Удаляет товар из корзины.

### Заказы

`POST /api/orders/`

- Создает заказ из текущей корзины.
- Принимает JSON: `full_name`, `phone`, `email`, `address`.
- Обязательные поля: `full_name`, `phone`, `address`.
- Если пользователь авторизован, заказ привязывается к нему.
- После создания заказа корзина очищается.
- Возвращает `order_id` и `redirect_url`.

## Frontend-логика

JS-файлы лежат в `meatdjango/static/js/`.

### `api-client.js`

Общий клиент для запросов:

- читает CSRF cookie;
- добавляет `X-CSRFToken` для небезопасных HTTP-методов;
- отправляет `credentials: 'same-origin'`;
- парсит JSON;
- выбрасывает ошибку, если HTTP-ответ не `ok`;
- форматирует цены через `Intl.NumberFormat('ru-RU')`;
- обновляет бейдж количества товаров в корзине.

### `auth-login.js`

Обрабатывает форму входа:

- отправляет `POST /api/auth/login/`;
- при успехе редиректит пользователя на профиль;
- при ошибке показывает сообщение.

### `auth-register.js`

Обрабатывает форму регистрации:

- отправляет `POST /api/auth/register/`;
- отображает ошибки валидации Django forms;
- при успехе редиректит на профиль.

### `auth-nav.js`

Обрабатывает кнопку выхода в шапке:

- делает `POST /api/auth/logout/`;
- редиректит на главную.

### `products.js`

Управляет страницей каталога:

- загружает категории через `/api/categories/`;
- загружает товары через `/api/products/`;
- поддерживает поиск и фильтр по категории;
- обновляет URL query parameters через `history.replaceState`;
- рисует карточки товаров;
- добавляет товар в корзину через `/api/cart/items/`.

### `product-detail.js`

Обрабатывает кнопку добавления товара в корзину на странице товара.

### `cart.js`

Управляет корзиной:

- загружает корзину через `/api/cart/`;
- рисует строки корзины;
- увеличивает и уменьшает количество;
- удаляет товар;
- обновляет итоговую сумму и бейдж корзины.

### `checkout.js`

Управляет оформлением заказа:

- загружает корзину;
- показывает состав заказа;
- отправляет `POST /api/orders/`;
- при успехе очищает бейдж корзины и переходит на страницу успешного заказа.

### `home-reviews.js`

Управляет отзывами на главной:

- загружает опубликованные отзывы;
- отправляет новый отзыв на модерацию;
- показывает сообщения об успехе или ошибке.

### `about-news.js`

Загружает новости для страницы `О компании`.

### `news-detail.js`

Загружает детальную информацию о новости по `news_id`, который передается через `data-news-id` в шаблоне.

### `profile.js`

Управляет личным кабинетом:

- загружает данные пользователя;
- загружает историю заказов;
- загружает отзывы пользователя;
- позволяет удалить свой отзыв.

## Пользовательские сценарии

### Просмотр каталога и добавление в корзину

1. Пользователь открывает `/products/`.
2. `products.js` загружает категории и товары через API.
3. Пользователь может искать товар по названию и фильтровать по категории.
4. При нажатии `В корзину` отправляется `POST /api/cart/items/`.
5. Корзина сохраняется в session.
6. Бейдж корзины в шапке обновляется без перезагрузки страницы.

### Оформление заказа

1. Пользователь открывает `/cart/`.
2. `cart.js` загружает корзину через `/api/cart/`.
3. Пользователь меняет количество или удаляет товары.
4. Пользователь переходит на `/checkout/`.
5. `checkout.js` показывает состав заказа.
6. Пользователь вводит имя, телефон, email и адрес.
7. Отправляется `POST /api/orders/`.
8. На сервере создается `Order` и связанные `OrderItem`.
9. Корзина очищается.
10. Пользователь переходит на `/order-success/`.

### Регистрация и вход

1. Пользователь открывает `/register/` или `/login/`.
2. JS отправляет данные на API авторизации.
3. Django создает пользователя или проверяет учетные данные.
4. После успеха пользователь перенаправляется на `/profile/`.

### Личный кабинет

1. `/profile/` доступен только авторизованным пользователям.
2. `profile.js` загружает данные пользователя, заказы и отзывы.
3. Заказы берутся только для текущего пользователя.
4. Отзывы пользователя можно удалить через API.

### Отзывы

1. На главной странице пользователь заполняет форму отзыва.
2. `home-reviews.js` отправляет `POST /api/reviews/`.
3. Отзыв сохраняется с `is_published = False`.
4. Администратор публикует отзыв в Django admin.
5. После публикации отзыв появляется в `GET /api/reviews/`.

### Новости

1. Администратор создает новость в Django admin.
2. Для показа на сайте нужно отметить `is_published`.
3. Новости выводятся на странице `/about/`.
4. Детальная страница `/news/<id>/` загружает данные через API.

## Важные технические детали

- В проекте активно используется `@ensure_csrf_cookie`, чтобы JS мог отправлять POST/PATCH/DELETE запросы с CSRF-токеном.
- JSON body парсится вспомогательной функцией `_parse_request_json`.
- Для API, требующего авторизации, используется кастомный декоратор `_api_login_required`, который возвращает JSON 401 вместо HTML-редиректа.
- Для корзины есть нормализация `_normalize_cart`, которая чистит некорректные значения в session.
- Цены сериализуются как строки, чтобы не терять точность `Decimal`.
- Часть страниц рендерится почти пустой и заполняется JavaScript через API.
- Поиск товаров реализован не SQL-запросом `icontains`, а фильтрацией списка в Python через `casefold()`.
- Поле `Product.available` учитывается при добавлении товара в корзину, но список `/api/products/` возвращает и доступные, и недоступные товары.
- Оба варианта оформления заказа существуют: HTML view `checkout` обрабатывает POST формы, но реальный шаблон сейчас использует JS и `POST /api/orders/`.

## Известные проблемы и нюансы

- В репозитории нет `requirements.txt`, поэтому другому ИИ или разработчику нужно восстановить зависимости вручную.
- Файл `templates/meatsite/contacts.html` выглядит как текст с поврежденной кодировкой: вместо нормальной кириллицы отображаются символы вида `РљРѕРЅС‚Р°РєС‚С‹`. Его стоит перекодировать или восстановить.
- В `settings.py` хранится dev `SECRET_KEY`, `DEBUG = True`, `ALLOWED_HOSTS = []`. Это нормально для учебного проекта, но не для production.
- В базе SQLite файл `db.sqlite3` в списке файлов не обнаружен. Возможно, его нет в git, и после клонирования нужно выполнить миграции и наполнить данные через админку.
- В проекте есть медиа-файлы товаров и новостей, но сами записи в базе данных могут отсутствовать, если нет локального `db.sqlite3`.
- Автоматическая генерация slug в `save()` перезаписывает slug каждый раз при сохранении категории или товара. Если переименовать товар, его URL изменится.
- `prepopulated_fields` в админке для slug есть, но фактически slug все равно перегенерируется в методе `save()`.
- Заказы помечаются `is_paid=True` сразу при создании, реальной оплаты в проекте нет.
- У формы контактов нет backend-обработчика, страница содержит только контактную информацию и карту.
- Тесты фактически не реализованы: `meatsite/tests.py` пустой или стандартный.

## Как запустить локально

Предполагаемый запуск из папки `meatdjango/`:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install django pillow
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

После запуска:

- сайт: `http://127.0.0.1:8000/`;
- админка: `http://127.0.0.1:8000/admin/`.

Для заполнения сайта нужно через админку добавить:

- категории;
- товары;
- новости;
- при необходимости опубликованные отзывы.

## Что важно учитывать при доработке

Если другой ИИ будет изменять проект, ему лучше сначала смотреть эти файлы:

- `meatdjango/meatsite/models.py` - структура данных;
- `meatdjango/meatsite/views.py` - вся бизнес-логика и API;
- `meatdjango/meatsite/urls.py` - маршруты;
- `meatdjango/templates/base.html` - общий layout;
- `meatdjango/static/js/api-client.js` - общий JS-клиент;
- конкретный JS-файл страницы, которую нужно менять.

Типичные доработки:

- исправить кодировку `contacts.html`;
- добавить `requirements.txt`;
- добавить фикстуры или seed-команду для товаров/категорий;
- добавить тесты API корзины, заказов, авторизации и отзывов;
- улучшить поиск товаров через ORM `icontains`;
- не перегенерировать slug при каждом сохранении, если slug уже задан;
- разделить HTML views и API views по файлам, если проект начнет расти;
- добавить пагинацию товаров;
- добавить обработку формы обратной связи;
- заменить учебную оплату `is_paid=True` на реальный статус оплаты или убрать флаг из пользовательского сценария.
